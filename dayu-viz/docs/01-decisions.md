# 决策登记

> 状态只允许三种实质值：**已批准（带日期）** / **待批准（卡在谁那里）** / **未决（最迟何时需要）**。
> **未批准不当作事实。** 空白不是"已批准的确定值"。

| --- | --- | --- | --- |
| `Q01` | <要决定什么（写问题，不写方案）> | <状态 + 日期 + 依据> | `M<N>` |
| `Q02` | | | |

> 影响节点为空的行，说明这个决策既不紧急也不属于本项目——考虑删掉。

## 2. 批准记录

每次批准记一段。**第三项最常被省略，也最重要。**

```markdown
### Q<NN> 批准依据（<日期>）

用户对 <明确选项，如"选择 A「清理优先」"> 回复"<原话或要点>"（<日期>）。

关联：<用例 ID 列表>、<节点>。

**本批准不覆盖**：<明确写出这次批准没有授权什么——
例如"不批准其他子项""不批准开始编码""批准的是验收目标，不是性能结果">。
```

## 4. 可逆 vs 不可逆

| 类型 | 谁决定 |
| --- | --- |
| 可逆工程细节（框架、目录、命名、内部实现） | 执行者自行决定 |
| **不可逆产品语义**（数据外发、质量门槛、许可证、发布账号、费用授权） | **必须用户批准，不得代批** |
