# 交付清单与 DoD

> 宣称"项目完整交付"前，本文件的自检必须全绿。
> **两种"完成"分开**：文档交付完成 ≠ 产品完整交付。
> `BLOCKED`、`NOT_RUN`、只在 mock 通过、只有截图、只有源码、构建绿、测试总数好看——**均不算完整交付**。

## 1. 交付件

| 类别 | 内容 | 状态 |
| --- | --- | --- |
| 源码 | 全部组件源码 + **全部实际测试与 fixture** | |
| 锁定 | 精确工具链与依赖锁定；协议版本/schema/黄金向量 | |
| 许可 | `LICENSE`、`NOTICE`、第三方组件与版本/许可清单；资源来源与许可 | |
| 产物 | 可运行包/镜像 + **SHA-256**；刷写/分区清单（如适用） | |
| 文档 | 安装、配置、日常使用、**问题定位**、退出卸载、升级与**恢复** | |
| 证据 | 测试结果、RED/GREEN 记录、真实环境证据、性能数据、验收记录、遗留限制 | |

> 不把"应用镜像"当"全量刷写包"；升级失败必须能按文档恢复；测试与 fixture 一起交付。

## 2. manifest

```json
{
  "name": "<项目名>",
  "version": "<版本>",
  "built_at": "<ISO8601>",
  "source_hash": "<内容哈希或提交哈希>",
  "artifacts": [
    {"path": "<相对路径>", "sha256": "<…>", "bytes": 0}
  ],
  "toolchain": {"<工具>": "<精确版本>"},
  "dependencies": {"<依赖>": "<精确版本>"},
  "protocol_versions": {"<协议>": "<版本>"}
}
```

> 没有版本控制提交时，用**内容哈希**标识版本。
> **不为满足形式而擅自提交或发布仓库。**

## 3. 质量与真实性

- [ ] 已批准的质量/时延/可靠性/体验标准通过；**统计含失败分母，未达标不改口径**
- [ ] **无已知的违反需求类缺陷**；例外需用户明确修改范围并同步所有文档
- [ ] 上游文档、类型定义、模拟器、历史实验与本项目真实证据**各自标注，不互相冒充**

## 4. 操作验证

- [ ] 普通用户可安装运行，**无需日常管理员**
- [ ] **不修改全局安全策略**（防火墙、TLS、代理、驱动）
- [ ] 从交付源码可按文档构建功能等价产物
- [ ] 测试进程/监听/临时文件已清理；**用户既有环境未被破坏**
- [ ] 用户按说明书完成完整流程（安装 → 配置 → 核心操作 → 状态查看 → 失败处理 → 退出）

> 若要求**逐字节可复现构建**，需**另行批准**——不要默认宣称已达到。

## 5. 脱敏检查

- [ ] 无真实凭据/密钥/令牌
- [ ] 无设备标识（MAC、序列号）
- [ ] 无真实项目名、路径、会话内容
- [ ] 无用户数据、音频、转写正文、日志正文
- [ ] 无企业内部信息（网络配置、账号、主机名）
- [ ] 凭据仅存于专用凭据存储，**不在配置文件/命令行/日志/构建产物/fixture 中**

## 6. 遗留限制

```markdown
| 限制 | 现象 | 影响范围 | 触发条件 | 规避方式 | 是否阻塞 |
```

> 不为凑数弱化描述，也不为免责夸大影响。阻塞项必须解决或由用户明确修改范围。

## 7. 发布授权

| 项 | 状态 |
| --- | --- |
| 本地完整交付 | <进行中/完成> |
| 公开发布（建仓/推送/tag/Release） | <**未授权** / 已授权（日期）> |
| 发布前审查（账号、归属、脱敏、署名） | |

> 发布是**独立授权项**。已明确"先本地交付、验收后再决定"时，**不要提前推送**。
