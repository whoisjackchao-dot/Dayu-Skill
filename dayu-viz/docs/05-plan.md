# 里程碑与 Definition of Ready

> 节点定义**不是工期承诺**。当前状态：<哪些已验收、哪些未开始>。
> 关联：<决策登记>、<契约目录>、<测试矩阵>

## 1. 节点序列

| 节点 | 名称 | 状态 |
| --- | --- | --- |
| `M0` | 可测试需求与决策基线（**不是可用软件**） | |
| `M1` | <第一个纵向增量> | |
| … | | |

> `M0→M1→…` 是默认**风险优先**路线，**不是必须等待整个模块完成的瀑布流程**。
> 前一节点期间可独立做研究/准备授权，但**任何探索不绕过用户授权**。

## 2. 里程碑卡片

```markdown
### M<N>：<名称>

- **用户价值**：<用户因此能做什么，用户视角一句话>
- **入口**：<前置节点 + 必须已冻结/已批准的契约与决策>
- **交付**：<本节点新增的可运行能力与产物>
- **测试策略**：<哪些走 T（先测试）/ C（契约）/ H（实机）>
- **适用用例**：<用例 ID 列表>
- **演示脚本**：<演示哪几个场景，**必须含失败场景**>
- **出口判据**：<什么条件下可关闭本节点>
- **明确未交付**：<本节点不含什么>
- **不算完成**：<2–3 条"看起来做完了"的伪装>
```

## 3. Definition of Ready

故事开工前七条全中：

- [ ] 1. 一个可演示的用户结果，对应 `R` 编号；**明确不包含什么**
- [ ] 2. 正常/边界/失败用例及预期；T/C/H/D 已分类
- [ ] 3. 依赖的 `Q` 项已决议；字段/阈值/数据来源已冻结到**足够测试**
- [ ] 4. 夹具、环境、可观察输出、清理方法可用；需费用/高风险动作已获**明确授权**
- [ ] 5. 入口/出口、副作用所有权、取消/重试/去重、资源限额明确
- [ ] 6. 能识别 RED 失败原因；上游探索与业务测试分开
- [ ] 7. 与现有系统的兼容范围明确；有失败后的停止/恢复方案

> **未知能力先进入限范围 spike**，不在未验证假设上批量编码。
> spike 出口可以是"不支持"，但**不算功能交付**——返回设计，**不静默降低需求**。
