# 脱敏走查：一个真实项目的各阶段产物长什么样

> **来源与脱敏说明**：本走查来自一个真实的个人硬件+软件项目——"蓝牙语音输入器 + 编辑器状态屏"（设备按住讲话 → 转写 → 只追加到编辑器输入框，绝不自动提交）。
> 领域专属内容已抽象：具体芯片/协议/云服务/编辑器 API 均以 `<…>` 表示。**保留的是方法，不是领域。**
> 原始提取材料见 `provenance/extraction-notes.md`。

---

## 阶段 0：可行性核查

### 结论范围声明（第一句就限定它不是什么）

> 结论范围：文档／源码／本机隔离验证，**不是**设备和云端到端验收。

**为什么重要**：没有这句，下一轮会把"本机隔离跑通"读成"整条链路可用"。

### 环境基线（节选，含边界声明）

| 项 | 值 |
| --- | --- |
| 硬件 | <机型>、<CPU>、<内存>；<GPU> |
| 系统 | <OS> <Build> |
| 工具链 | `<可执行文件完整路径>`、`--version` 输出、**二进制 SHA-256** |
| 依赖 | 匹配的插件包版本 `<x.y.z>` |

> 基线**不能证明**：枚举到适配器 ≠ 设备已配对可用。
> 空闲内存随负载变化，**不作为性能承诺**。

### 隔离实验（E 编号）

| ID | 操作 | 观察 | 可得结论 |
| --- | --- | --- | --- |
| `E03` | 向 `<普通追加接口>` 额外携带目标会话 ID | 请求被接受，但目标未被保护 | **不能宣称该接口原生支持按会话追加** |
| `E07` | 用隔离环境复现会话切换竞态 | 额外字段没有保护目标 | 该方法**不可依赖** |

> 注意结论写法：不是"这个接口不行"，而是**"不能宣称 X"**。结论动词与证据等级匹配。

### 缺口台账（B 编号）

| ID | 缺口 | 需要的证据 | 当前处理 |
| --- | --- | --- | --- |
| `B01` | 运行中安全封装输入框 | 加载、引用生命周期、附件/撤销、忙态、切换会话测试 | **首要阻断门槛** |
| `B02` | 多实例 / ACK 丢失 / 代次 | 重启、第二客户端、写后 ACK 丢失不重填 | **不提供跨崩溃 exactly-once 承诺** |
| `B06` | 电源与本地化显示 | 息屏保连、电池实测、字体与长文本 | **不承诺续航数字** |

> "当前处理"列写的全是**口径限制**，不是"待补充"。这就是"不确定必须可表达"。

### 工作审视报告（四段式节选）

**原定目标**：确认已选需求具备可信技术路径，并交付有依据的设计文档，**而非开始实现**。

**发现的问题与修正**：

| 严重程度 | 具体问题 | 原因 | 本次修正 |
| --- | --- | --- | --- |
| 必须改正 | 把 `<某接口>` 当成按会话安全写入 | **只凭接口名称推断语义** | 隔离环境复现，改为"插件内事务验证"门槛 |
| 应当改正 | 验收主题不可执行 | 只写了主题，没写用例 | 补充带 ID 的可执行用例与追踪表 |

> "原因"列写**真实原因**（"只凭接口名称推断语义"），不写"疏忽"。这样同类风险才能被系统性发现。

**下次重点关注**：先通过 `B01`/`B02`，再进入硬件与云联调。**若新会话继续，请将这两份文档作为上下文；不能依赖跨会话记忆代替设计约束。**

> 这一句是整套长上下文协议的原点。

## 阶段 1：需求分析

### 需求表（写行为与禁止项，不写数值门槛）

| 编号 | 已确认要求 |
| --- | --- |
| `R07` | 按住录音、松开结束；单次最多 30 秒，**到时硬停** |
| `R11` | 追加到已有输入框文字末尾，**不覆盖、不自动提交** |
| `R18` | 用量范围为绑定会话；**不显示账号剩余额度**，**缺失值显示未知** |
| `R22` | 松开录音键至文本追加通常不超过 5 秒，**需实测验收** |

> `R22` 写了"需实测验收"但**没写数字门槛**——门槛进 `G`/`Q`，因为它需要单独批准。

### 验收门槛（独立编号、含分母）

| 门槛 | 判定标准 |
| --- | --- |
| `G1` | 目标会话内的追加行为可被自动化断言，且不产生提交 |
| `G8` | 发布门槛：许可、脱敏、恢复说明齐备 |

**测量口径单列**：

> 5/15/30 秒各测试 20 次，每组**至少 19 次**在松开后 5 秒内成功填入；
> **网络失败、超时和填入失败均计未达标，不从 20 次分母中剔除**。
> 冷启动 / 重连 / 主动取消**另测**。

### 决策登记（含"该批准不覆盖什么"）

> `Q03`（用户对"各 20 次、每组至少 19 次、失败不剔除"回复"接受"，2026-09-15）。
> 关联 `PERF-01`、`M3`/`M5`；**批准的是验收目标，不是性能结果**。

> `Q02`（用户对整组建议回复"接受"）。**此回复不批准其他 Q02 项目或开始编码。**

> `Q06`（用户回复"好的，可以"）。**该批准不包含长按具体时长或新增手势。**

### 待审定事项与停止条件

> 若方案 A 的关键门槛失败，应**重新提交设计选择，而不是自动退到方案 C**。
> 未通过门槛，**不发布"完整可用版"，也不偷偷采用剪贴板、模拟按键或直接提交消息替代**。
> **设计批准不等于完成实机验证。** 以上验证只能在获得编码/测试授权后实施；当前只定义判定条件。

## 阶段 2：项目规划

### 里程碑卡片（节选 M1）

```markdown
### M1：安全草稿通道最小闭环

- 用户价值：从受控主机输入一段测试文字，只追加到正确输入框，不提交。
- 入口：M0；相关 IPC / 授权 / 取消契约可测。
- 交付：最小入口、启动/绑定、适配器、同代次去重和取消结果。
- 测试策略：会话校验、单事务、去重、取消与 TTL 规则先红后绿；
              平台接入先契约研究后集成验证。
- 适用用例：`TUI-01`—`TUI-18`、`TX-03`、`TX-10`—`TX-14`、`SEC-01/02/05/06` 适用部分。
- 演示脚本：A/B 会话切换、已有附件草稿、忙态、ACK 丢失、取消过晚；
            **记录没有新模型消息**。
- 出口判据：所有本节点适用用例通过；运行路径确为预期路径；用户看过演示与已知风险。
- 明确未交付：设备采音与云识别，**不能称语音输入器完成**。
```

> 演示脚本里"记录没有新模型消息"就是一条**否定式可观察断言**——和需求里写禁止项是同一个习惯。

### 冻结范围二分表

| 冻结 | 不冻结（各自里程碑前） |
| --- | --- |
| 六个桥接操作的路径、方法、认证、媒体类型、状态码 | 线协议、UUID、帧布局、摘要算法（`M2` 前，见 `C07`） |
| 操作状态机与线性化点 | 语料与准确率细则（验收前，见 `C09`） |
| 去重指纹、墓碑、容量、在途期限 | 字体、按键阈值、息屏参数（`M4` 前） |

### 线性化点（一句话，且排除其他候选时点）

> **线性化点**是插件内**同步**更新输入框并记录结果的那一步；
> **不是**用户松键、**不是**发出取消、**不是** HTTP 返回时间。

配套穷举两种顺序：

- 取消先到 → 写入身份进入终态 `cancelled`，同 ID 的迟到写入**必须被墓碑拒绝**。
- 写入先发生 → 取消返回 `already_applied`，**不自动删除**已写入的草稿。
- 无法确认 → `uncertain`，**人工检查，禁止自动重放/回滚**。

### 明确声明不提供的保证

> 严格要求"发出取消后即使通知尚未到达也绝不出现文字"，**无法靠普通异步消息保证**。
> 如用户要求这一更强语义，**必须另行评审**受限时钟/租约/确认交互；本稿**不偷偷声称已满足**。

## 阶段 3–4：开发与测试

### 用例表（四列固定）

| ID | 层级 | G / W | T：可观察断言 |
| --- | --- | --- | --- |
| `TUI-01` | T | G 目标会话已绑定；W 追加"修复 API" | T：输入框恰为"修复 API"；附件不变；**消息数不变**；返回 `applied` |
| `TUI-04` | T | G 绑定到 A；W 向 A 发送但目标被切到 B | T：A/B 草稿**都不因请求改变**；返回 `target_mismatch`；**无提交** |
| `TUI-17` | T+C | W 实际运行并抓取传输记录 | T：记录中**无**提交/消息/命令/权限应答；**不是只 grep 源码** |
| `TX-13` | T | G 录音进行中收到挂起通知 | T：即使未满保留期也不重试旧段；迟到回调不发起追加；已写入草稿保留 |

> `TUI-17` 的层级是 `T+C`——可叠层。它的断言本身就是"否定式 + 反作弊"（**不是只 grep 源码**）。

### 变异敏感性

> `TUI-09` 的错误变异示例：**移除去重后同一请求出现两次文字，必须被捕获。**
> **移除目标校验必须使测试失败。**

### T 类证据字段（节选）

| 字段 | 示例 |
| --- | --- |
| RED | `pytest -k target_mismatch` → 失败断言："B 的草稿被修改了" |
| GREEN | 同命令 → 1 passed |
| fixture 版本 | `<fixture 路径>` @ `<哈希>` |
| 残余风险 | 未覆盖多客户端并发场景 |

> RED 的失败断言必须是**业务规则**（"B 的草稿被修改了"），不是"模块导入失败"。

## 阶段 5：验收

| 门槛 | 样本/分母 | 达标数 | 结论 | 证据路径 |
| --- | --- | --- | --- | --- |
| `G1` 时延 | 20（5 秒录音组） | 19 | `PASS` | `evidence/M3/PERF-01/` |
| `G2` 准确率 | 30 | 27 | `PASS` | `evidence/M3/ASR-10/` |

**同时报告**：总尝试数、成功数、达标数/全部尝试、超时数、取消数、失败数。

**失败处理**：

> 若未达标，报告各阶段耗时后**提出选择**，不擅自截断录音、降低识别质量、改为自动发送或放弃已批准能力。

**自动化裁决者纪律**（这个项目踩到的真实坑）：

> 评分器自身必须有**先失败的黄金测试**。
> **不得用 LLM 自评作为唯一裁判。**
> 归一化**不得**删除路径分隔符、小数点、负号、版本号中的点——不能因为"标点另计"把 `1.5` 与 `15` 视为相同。
> **不得**把大段替换合并计为"1 处轻微修正"从而掩盖整句重写。
> 参考文本**运行前冻结**，**不得看到模型输出后改参考以让它通过**。

## 阶段 6：交付

**四类 DoD 全绿**：功能与行为 / 质量与真实性 / 交付件 / 操作验证。

**容易漏的三条**（来自真实项目的检查表）：

> 不把"应用镜像"当"全量刷写包"。
> 升级失败要能按文档**恢复**。
> 测试与 **fixture** 要一起交付，否则"测试通过"无法被复核。

**发布是独立授权项**：

> `Q07` 已批准先完整本地交付（源码、产物、自动化测试、构建/使用说明、许可文件），
> **GitHub 建仓/推送/Release 不属本次完成条件，也未获授权**；验收后由用户另行决定。

## 这个走查示范了什么

| 观察 | 对应铁律 |
| --- | --- |
| 每份文档开头都声明"本文不是什么" | 防误读 |
| 结论写成"不能宣称 X"而不是"X 不行" | 证据分级与动词分级 |
| 缺口台账的"当前处理"写口径限制 | 不确定必须可表达 |
| 状态机把 `uncertain` 作为一等终态 | 不能用假值掩盖 |
| 批准记录带"不覆盖什么" | 批准有边界 |
| 冻结范围表右列都带时点与依据 | 可逆不提前冻、不可逆不延后冻 |
| 明确声明"无法保证的强语义" | 不偷偷声称已满足 |
| 演示脚本含失败场景与否定式断言 | 只跑 happy path 不算完成 |
| 未达标时"提出选择"而不是"改门槛" | 不虚构 |
| 发布与本地交付分开授权 | 不擅自扩大授权 |
