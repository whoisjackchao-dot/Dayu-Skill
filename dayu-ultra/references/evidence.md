# 证据：分级、边界与不可伪造性

本文件回答一个贯穿所有阶段的问题：**"这句话凭什么算数？"**

## 1. 五级证据

每一条结论都必须能归入且只归入一级。等级不是修辞，是这行结论**能被用来支撑什么**的边界。

| 标记 | 含义 | 能支撑 |
| --- | --- | --- |
| **实测** | 本次实际运行命令、调用隔离服务或观察系统所得 | 可以作为行为与性能结论 |
| **类型/源码** | 读取了匹配版本的类型定义或固定提交的源码，但**未运行**对应功能 | 只能支撑接口形状，不能支撑运行行为 |
| **官方文档** | 厂商明确提供的接口或约束 | 支撑"接口存在且有此约束"；**不等于**账户/设备已验证 |
| **拟定设计** | 本项目新规则 | 支撑"我们打算这么做"；**不能标成现成功能** |
| **未验证** | 尚需账号、设备或实现验证 | 明确列为门槛；不得在验收文档中当已通过 |

**每条证据都要绑定可复述的条件**：日期、版本/提交、环境、验证范围。没有条件的"已确认"不可复现，等于不可信。

## 2. 结论范围声明

在每份核查/验收文档开头写一段**结论范围**，明确它**不是**什么：

> 结论范围：文档／源码／本机隔离接口验证，**不是**设备和云服务端到端验收。

这段声明的作用是防止后续会话把局部证据外推成整体结论。没有它，文档会被误读——被误读的文档比没有文档更危险。

## 3. 环境基线

在做任何实测结论之前，先固定一份环境基线，并写清它能证明的边界。至少包含：

| 类别 | 记录内容 |
| --- | --- |
| 硬件 | 机型、CPU、内存、GPU、对外设的可见性 |
| 系统 | OS 与 Build、区域/策略相关项 |
| 工具链 | 可执行文件**完整路径** + `--version` + 二进制 SHA-256 |
| 依赖 | 锁定的依赖版本、匹配的插件/库版本 |
| 本次边界 | 这份基线**不能**证明什么 |

基线的两条铁律：
- **基线不构成任何性能承诺**（"空闲内存随负载变化，不作为性能承诺"）。
- **枚举不等于操作**（"枚举到蓝牙适配器"只证明电脑端有适配器，不证明设备已配对或可用）。

## 4. 缺口台账

把"未验证"从一句标注升级为带 ID 的台账。列：

| ID | 缺口 | 需要的证据 | 当前处理 |
| --- | --- | --- | --- |
| B01 | <具体缺口> | <可执行的测试/测量动作> | <现阶段的口径限制；如需标为"首要阻断门槛"> |

"需要的证据"必须写成**可执行的动作**，不能写成"进一步调研"。"当前处理"必须写**明确的口径限制**（"不提供跨崩溃 exactly-once 承诺"），而不是"待补充"。

**缺口台账是唯一允许出现"未完成"的地方。** 缺口从台账里消失的唯一方式是：有证据，或者用户明确修改范围。

## 5. 工作审视报告

每轮工作结束时写一份四段式自我审视。这是防止"越做越偏"的主要机制：

| 段 | 内容 | 作用 |
| --- | --- | --- |
| **原定目标** | 本轮范围：做什么、**不做什么** | 给"完成情况"提供判定基准 |
| **完成情况** | 复选框清单，逐条 `[x]`/`[ ]`；未完成项必须写原因 | 防止用"基本完成"模糊表述 |
| **发现的问题与修正** | 表：`严重程度 \| 具体问题 \| 原因 \| 本次修正` | 登记已被推翻的旧结论及替代表述 |
| **下次重点关注** | 下一轮入口条件 + 指定上下文载体 | 跨会话交接的锚点 |

严重程度只用两级：**必须改正**（影响正确性/安全/验收）与**应当改正**（影响效率/可维护性）。三级以上会退化为"都很重要"。

"发现的问题与修正"的**原因**列必须写真实原因（"只凭接口名称推断语义"），不写"疏忽"。写真实原因才能定位同类风险。

## 6. 结论动词分级

区分三种证据，靠的是**动词**，不是形容词：

| 证据等级 | 允许的表述 | 禁止的表述 |
| --- | --- | --- |
| 实测 | 已确认、实际有效、观察到 | — |
| 类型/源码 | 类型声明为、源码显示 | 运行时支持、可以调用 |
| 官方文档 | 厂商声明、文档提供 | 已验证、实测可用 |
| 拟定设计 | 本项目拟定、计划 | 已实现、现成功能 |
| 推断 | 不排除、不能据此断言、**正确结论是…** | 显然、必然、应该可以 |

**不允许外推的三类句子**（每种都要改写成限定表述）：

- 把局部当整体：`不能宣称该接口原生支持 X` / `不能凭 schema 假设运行时会拒绝未知字段`
- 把上游当本项目：`上游作者的实机声明不等于本次替用户完成实机验收` / `不能从上游功能表推断已经具备`
- 把未测当已测：`未做二进制可复现构建校验，不宣称二进制逐字节来自该提交`

## 7. 什么不算证据

以下都**不能**支撑"功能已完成"：

| 不是证据 | 为什么 |
| --- | --- |
| 文档里写了测试用例 | 文档可以支持方法论；是否执行只能由 RED/GREEN 证明 |
| 构建绿 | 编译通过不证明行为正确 |
| 测试总数好看 | 数量不是覆盖 |
| 只在 mock 上通过 | mock 通过证明不了真实组件行为 |
| 只有截图 / 只有源码 | 都不是可复现的行为证据 |
| 覆盖率百分比 | 覆盖率只能发现空白，不判定关键行为；**不要设虚构的覆盖目标** |
| 上游的类型定义 / 模拟器 / 历史实验 | 各自标注，**不能互相冒充** |
| 一次成功的手工试用 | 未固定样本与分母，不可复现 |

## 8. 测试隔离与替身边界

测试可以替身化，但**替身范围是契约的一部分**，必须写下来。

**可以替身：**

- 时钟（用可控时钟推进 TTL，不要让测试真实等待数分钟）
- 远端响应（外部服务用**本地受控服务**，记录实际请求与调用次数）
- 收包调度（用屏障/调度器控制顺序，**不靠随机 sleep 碰运气**）

**必须运行真实实现：**

- 真实状态机、解析器、请求生成、去重、数据清理逻辑
- 关键错误变异至少有一个测试能抓住

**替身的三条硬约束：**

1. **黄金期望不能由待测代码生成。** 期望值独立计算（手推/独立实现），否则测试是自证。
2. **只在明确授权的门槛访问付费云端**，不让 CI 无控制地产生费用。
3. **用测试专用环境隔离**：专用 HOME/XDG、独立端口、测试会话；并确认真实副作用没发生（例如"没有向模型发出消息"）。

**HIL（实机/人工）不能自动化替代**：物理证据必须来自真设备；软件模拟不能冒充。HIL 可以自动化**驱动**（设备驱动、故障注入、自动采集），但"是否真的响了/亮了/连通了"要真实观察并记录环境。

## 9. RED 的严格定义

**RED 必须因缺失或错误的行为而失败。** 以下都**不构成** RED：

- 模块无法导入
- 工具未安装
- API Key 缺失
- 网络断开

这些是**环境问题**，不是行为证据。允许先搭建必要的测试接口或最小空壳，但**不能先完成业务实现再补一条"看起来红过"的记录**。

真实 RED 的例子（因业务规则失败）：

- 错误会话被写入
- 到期后仍可重试
- 缺帧仍调用了下游服务

## 10. 测试结果状态枚举

只用这五个值，不要自创：

| 状态 | 含义 |
| --- | --- |
| `NOT_RUN` | 用例已定义但尚未执行 |
| `BLOCKED` | 依赖缺失（设备/额度/阈值未批/环境），**记录解除条件** |
| `FAIL` | 已执行且未通过 |
| `PASS` | 已执行且通过 |
| `NOT_APPLICABLE_APPROVED` | 经用户批准不适用（需注明批准依据） |

**skip 不能自动算 PASS。** 判定阈值未批准 → `BLOCKED`，不是 PASS，也不是 FAIL。

## 11. 反模式

| 反模式 | 为什么是错的 | 正确做法 |
| --- | --- | --- |
| 用 0 代替未知 | 0 是一个**断言**，不是缺失 | 保留 `unknown` / `not_reported` / `known(value)` 的区别 |
| 用"预计可用"代替阻塞 | 掩盖了真实依赖 | 写明 BLOCKED 原因与解除条件 |
| 用"先交 v0 以后补" | 把未完成说成完成 | 明确列出未交付内容 |
| 失败样本剔除 | 分子好看、分母失真 | 失败计入分母；"失败不剔除" |
| 只报成功请求的 P95 | 隐藏失败 | 同时报告总尝试数、成功数、达标数/全部尝试、超时、取消、失败 |
| 用 P95 取代门槛 | 统计描述不等于验收判据 | 门槛就是门槛（如"每组至少 19/20"） |
| 看到模型输出后改参考 | 参考被人为对齐到结果 | 语料与参考文本运行前冻结 |
| 删失败测试 / 放宽断言 | 删除的是缺陷报告 | 修代码或修测试，但**不降低断言** |
| 关键缺陷只改症状 | 同类调用点继续出错 | 先补能复现的回归测试，再在共享接缝处修根因 |

## 12. 证据目录组织

- 按 `evidence/<milestone>/<caseID>/` 存放：manifest、结果、脱敏日志、照片/录像。
- **manifest 记录版本**：没有 VCS 提交时用内容哈希标识版本。
- **不为满足形式而擅自提交或发布仓库**——版本标识不等于获得提交/发布授权。
- 脱敏：不泄露真实 Key、MAC、企业项目名、音频、日志。
